# 补充对话合并记录

来源：用户指定的「娃娃心脏」产品讨论与当前 Android 迁移需求。本文只整理产品要求，不包含原始对话记录。

## 用户已经明确的要求

| 项目 | 明确要求 | 本次落实 |
| --- | --- | --- |
| 形态 | 手机 App；当前优先安卓 | Android 工程与可安装 APK，支持 Android 8.0/API 26 及以上 |
| 其他平台 | 旧对话曾要求 iOS、Android 同时支持 | 本轮优先 Android；共享界面可复用，iOS 原生层与签名尚未实现 |
| 硬件外观 | 用户选定「糖心」，心形比胶囊更好看 | 保留心形；设备页明确为糖心 |
| 放置 | 置入娃娃棉花内部 | 设计需允许取出维护；不把悬挂挂件当最终方案 |
| 娃体大小 | 主要 10–20 cm 及以上 | 不承诺兼容 5–10 cm 极小娃体 |
| 地域 | 首版中国大陆 | 中文体验；地图供应商与坐标转换待实际接入 |
| 定位 | 需要较完整路线 | App 新增手机实际位置采集、分段路线回看及 GPX 导出 |
| 离开手机 | 不需远程实时找回，但要继续记录，回来后同步 | 最终目标改为 BLE + 独立 GNSS + 本地存储；本版不伪装已完成硬件同步 |
| 型号 | 尚无样品、型号或协议 | 先实现 BLE 扫描与只读公开服务发现；补充待定通信协议草案 |
| 续航 | 用户希望免充，但又希望完整轨迹 | 有冲突尚未取舍，不宣称多年免充，也不视为已接受 3–7 天充电 |
| 情感体验 | 本任务选择共同回忆＋轻陪伴 | 延续，无强聊天或惩罚养成 |

旧对话最后一个“是否接受磁吸充电、约 3–7 天充一次”的问题没有得到用户回答。因此该频率不是已确认需求，也不是经样机测试的指标。以样机测量再做电源设计，不能照搬之前助手给出的数字。

## 参考方案中采纳的扩展

- 首次建档：名字、生日、陪伴性格；首次启动不要求蓝牙或位置权限。
- 娃娃旅行护照：从用户确认保存的城市生成印章，不伪造自动到达或地理验证。
- 心情记录：由用户主动选择，不把算法猜测当作真实心情。
- 奶油手账、樱花心事、应援票根：可选择视觉模板，保存与导出保留主题色和心情。
- 实际路线暂停、继续、结束；中断与暂停之间不画假连线。
- 精确位置不进入普通照片分享卡；导出 GPX 与备份时明确含位置数据。

## 暂不宣称已经实现

糖心独立轨迹同步、设备自动重连与断点同步、真实设备电量（除设备提供标准电量服务外）、硬件振动、硬件续航、地图底图、天气自动填入、语音日记、在线 AI、年度成册、上架、云同步。

另一段对话曾说参考链接不是照片类产品，这与本任务读取到的 Apple 商店介绍不一致；以本任务核实的 NuiDays 照片日记介绍为参考，不继续沿用错误判断。

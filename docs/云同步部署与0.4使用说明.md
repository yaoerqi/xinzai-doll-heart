# 心仔 0.4：多娃娃、多图相册与云同步

更新日期：2026-10-05。客户端与可部署服务已实现。本项目没有预置的公网服务器，完成下面的部署后才能跨手机联网同步。日常记录、多娃娃和相册可直接离线使用。

## 在 App 中使用

1. **迎接新娃娃**：页面上方「娃娃们 → 迎接一个新娃娃」，填写名字、生日与性格；下拉框切换当前娃娃。回忆、统计、日历和城市护照随娃娃切换。最多 20 个档案，归档后保留全部故事，可随时恢复。
2. **留下一组照片**：新建／编辑回忆，一次选择多张照片；最多 9 张。第一张是封面，可点「设封面」「←」「移除」。照片会压缩为长边不超过 1280 像素的 JPEG，手机原图不受影响。照片与归属娃娃都会随草稿保存。
3. **翻相册与分享**：打开回忆后点缩略图逐张查看。多图回忆默认生成拼图卡片；取消「将全部照片拼成一张」则仅使用封面。仍需自行检查分享图片和文字中是否包含地址。
4. **连接云端**：「我的 → 连接云同步」，填写已部署的 HTTPS 地址，注册或登录账号，勾选同步同意项。第一次注册需要管理员的邀请码，账号为 3–80 位字母、数字或邮箱格式字符，密码 10–128 位。邮箱只是账号标识，没有邮件验证或自助找回密码。
5. **另一部手机**：填写同一服务地址并登录同一账号，点「立即同步」。本机和云端的故事会合并。云账号切换也会合并当前本机资料，因此不同人使用同一手机时要先导出、整理本机资料。

自动同步在 App 前台、联网、没有打开其他编辑／查看窗口时运行：保存后约 8 秒尝试，前台约每分钟再次检查。安卓系统后台或锁屏时不保证同步；退出 App 前可主动点一次「立即同步」确认成功。只有正常保存的内容进入同步，草稿、尚未保存的旅程、蓝牙连接状态不上传。

退出云账号保留本机和云端资料；登录凭据通常 7 天过期。离线退出会清除本机登录，云端会话等到过期失效。原账号中已成功同步的回忆可以重新登录取回。

## 合并与删除规则

| 情况 | 结果 |
| --- | --- |
| 两部手机分别新增回忆／娃娃 | 合并保留 |
| 只有一边修改某条回忆 | 使用修改后的内容 |
| 同一条回忆同时修改 | 原记录与冲突副本都保留，详情页标注副本 |
| 同时编辑娃娃的名字／生日／性格 | 采用较新修订；娃娃档案不另建冲突副本 |
| 一边永久删除，一边离线修改 | 原记录保持删除，未同步的编辑以副本放进回收站 |
| 旧设备传回已删除内容 | 删除标记防止原记录复活 |
| 网络请求期间又写了新内容 | 保留本机新修改，下一次再同步 |
| 从 JSON 完全替换本机资料 | 暂停自动同步，确认本机结果后自行恢复 |

回收站的删除、恢复和永久删除也会同步到同账号设备。永久删除不会抹除已导出的 JSON 或管理员保存的服务器备份。云同步不是独立的历史版本备份，仍建议定期导出 JSON。

## 部署：Docker Compose＋HTTPS

准备一台可运行 Docker Engine 与 Compose v2 的服务器，以及指向该服务器的域名。下面命令在项目根目录执行，示例为 Linux shell；先把仓库代码放到服务器。客户端不绑定特定海外云平台，可以部署到自己在中国境内可访问的服务器。

```sh
cp cloud/.env.example cloud/.env
```

编辑 `cloud/.env`：

```dotenv
XINZAI_DOMAIN=你的真实域名
XINZAI_INVITE_CODE=替换为私下保存的长随机邀请码
XINZAI_ALLOWED_ORIGINS=
```

域名字段不带 `https://` 或路径。邀请码用密码管理器生成并私下提供给获准注册的用户；更换邀请码不影响已有账号。没有有效邀请码不能注册。`.env`、数据库、签名密钥已加入忽略规则，不应提交到公开仓库。

安卓走原生 HTTPS，不需要配置网页跨域来源。只有要让浏览器预览连接服务时，才填写准确来源，例如 `http://127.0.0.1:4173`；多个来源用英文逗号分隔。不要填写 `*`。

```sh
docker compose --env-file cloud/.env -f cloud/compose.yaml up -d --build
docker compose --env-file cloud/.env -f cloud/compose.yaml ps
docker compose --env-file cloud/.env -f cloud/compose.yaml logs --tail=80
curl https://你的真实域名/health
```

健康检查应返回 `{"ok":true,"protocol":1}`。App 内填写 `https://你的真实域名`。

Caddy 会申请并续期证书；域名 DNS 必须正确指向服务器，外部 80、443 端口可达，证书数据卷需要持久保留。这些是 [Caddy 自动 HTTPS 的要求](https://caddyserver.com/docs/automatic-https)。同步服务的 8787 端口仅在 Compose 内部暴露，由 Caddy 转发。不要另行把它开放到公网。

配置使用 Node 22 内置 SQLite，无第三方 npm 运行依赖。Docker 构建上下文仅包含服务必要代码，不带本地照片、文档或密钥。`XINZAI_TRUST_PROXY=1` 仅用于本配置中受信任的 Caddy 前置代理；自行运行服务时默认为关闭，不要在直接公开的 Node 端口上打开它。

发布后先用测试账号，在两部手机完成注册／登录、添加多图、双向编辑、删除及退出验证，再导入个人回忆。此轮没有服务器域名，因此未进行公网证书申请或真实安卓 HTTPS 跨机联调。

## 服务器数据与备份

SQLite 文件在持久卷 `library` 的 `/data/xinzai.sqlite` 中，普通容器重启和镜像更新保留数据。不要使用 `docker compose down -v`，它会移除数据卷。

进行停机一致性备份（先在服务器创建只允许自己访问的备份目录）：

```sh
mkdir -p backups
chmod 700 backups
docker compose --env-file cloud/.env -f cloud/compose.yaml stop sync
docker compose --env-file cloud/.env -f cloud/compose.yaml cp sync:/data backups/cloud-data
docker compose --env-file cloud/.env -f cloud/compose.yaml start sync
```

每次选一个新的备份目录名，保留整份 `/data`，包含可能存在的 WAL 文件。恢复时先停服务，把整份资料放回 `/data` 并确保 `node` 用户可读写，再启动；先在测试环境演练恢复。备份包含用户账号与回忆，应限制访问并保存在独立存储中。

服务端按账号隔离资料；密码经过带盐 scrypt 派生，数据库只存登录令牌的哈希。安卓登录会话使用 Android Keystore 支持的 AES-GCM 加密保存在私有目录，令牌不会交给页面或写入 JSON 备份。浏览器预览的会话只保存在当前标签页的 sessionStorage 中。

通信要求 HTTPS 并验证系统信任的证书，不接受忽略证书错误。**回忆本身不是端到端加密**：服务器运营者可以读取上传的照片、文字与路线。本机回忆也尚未做应用层加密。

## 容量与当前边界

- 每条回忆最多 9 张，每张导入源文件不超过 15 MB，只接收 JPG、PNG、WebP；超过 4000 万像素的图片拒绝处理。
- 每个资料库最多 20 个娃娃、500 条回忆（含回收站），云同步／JSON 备份整体上限约 25 MiB，永久删除标记最多 10000 条。超限会提示失败，不会自动裁剪照片或丢弃记录。
- 当前是整库同步，适合小规模试用；未做分片照片上传、大规模存储、计费或服务集群。浏览器本地存储可能更早遇到浏览器容量限制。
- 无自助密码重置、邮箱发送、账号注销界面或管理后台；需管理员人工运维。公开大规模运营前应补齐这些能力及恢复演练。
- 硬件 GPS／BLE 坐标接收仍需实物联调；本次云同步不会让尚未接通的硬件定位自动可用。

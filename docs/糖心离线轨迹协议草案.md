# 糖心离线轨迹协议草案（未绑定硬件）

这是为将来选型提供的接口要求，不代表任意车载 GPS 都能支持，也没有向发现的蓝牙设备写入这些命令。

## 已确定的方向

心形「糖心」内部需要 BLE 主控、独立 GNSS 接收机、轨迹存储、电源管理与电池。GNSS 负责定位，BLE 负责回到手机附近后同步；不需要 SIM 或蜂窝远程回传。

独立 GNSS 的天线、娃体填充、金属配饰、人体遮挡和室内使用都会影响接收。路线精度、体积、重量、定位采样频率与续航必须通过样机测量，不给出未经测量的固定数值。

## 选型可走的三条路

1. 有开放 BLE 轨迹导出协议的现成 GNSS logger：先验证完整导出与手机兼容，再判断能否装进糖心外壳。外壳拆改和电池兼容由硬件工程验证。
2. BLE 开发板 + 独立 GNSS 模块 + Flash：适合验证离线记录、时间同步和协议；开发板整体尺寸不作为最终产品尺寸。
3. 定制集成 PCB：在验证路线与能耗后，把电源、BLE、GNSS 和存储整合到心形结构中，成本和工期需供应商确认。

本次没有做芯片采购推荐或虚构现成产品兼容性。采购前至少要拿到服务 UUID、特征 UUID、数据格式、授权 SDK 与断点传输文档。

## 设备能力协商

连接后先读取：协议版本、设备唯一 ID、固件版本、GNSS 能力、电量/供电状态、存储容量、可导出 session 列表、设备时间与手机时间偏差。

未知协议设备只能展示“BLE 已连接，轨迹协议不支持”，不能显示“糖心已同步”。当前 App 的实现即遵守这个边界，只读发现的服务和可选标准电量服务。

## 待定义的 GATT 服务

硬件方确定正式 128-bit UUID 后填入配置，禁止把草案 UUID 当作现实设备协议。

| 特征 | 方向 | 用途 |
| --- | --- | --- |
| capability | read | 版本、设备身份、记录能力 |
| control | write with response | 经用户授权开始/暂停/结束记录、设置采样、请求 session |
| log-index | read/notify | 日志列表、首尾序号、总条数、摘要 |
| log-chunk | notify | 有序分块轨迹数据 |
| ack | write with response | 持久化成功后的确认与重传请求 |
| status | read/notify | 时间、定位有效性、充电、电量与存储状态 |

## 一条轨迹点的语义

至少包含 `deviceId`、`sessionId`、`sequence`、UTC 毫秒时间、WGS84 纬度经度、定位有效标记、精度估计、可选速度/海拔、电量，以及传输校验值。二进制端序、定点倍率、CRC 算法和分包方式由双方冻结文档并做测试向量。

无定位解时记录缺口状态，不用 (0, 0) 冒充真实位置。手机来源轨迹与设备来源轨迹分开标识。路线地图接入中国大陆供应商时，在显示层转换坐标；保留原始 WGS84 数据，避免重复转换。

## 断点同步与数据安全

1. 按设备 ID + session ID + sequence 去重。
2. 每一块校验通过后，先持久化，再发送 ACK。
3. 断连后从最后持久化序号恢复；不可仅凭蓝牙发送成功就删除硬件日志。
4. 清除设备日志必须由显式同步确认策略触发；可保留缓冲期。
5. 首次绑定需要物理确认或绑定令牌；附近扫描结果不是归属证明。
6. 错误版本、时间倒退、损坏 CRC、重复包、断电和存储写满都要有测试。

## 当前 Android 层已经做到哪里

- 实际 BLE 扫描，需要系统授权，扫描结束或 App 进入后台即停止扫描。
- 用户选择本轮发现的设备后建立 GATT 连接，读取公开服务列表。
- 如果设备提供标准 Battery Service，则读取实际电量；否则不显示猜测数字。
- 不写未知命令，不把附近设备自动绑定为糖心，不把手机路线伪装成设备离线路线。
- 手机定位提供先行可体验的路线采集；最终糖心不在手机旁的记录能力仍需真实硬件。

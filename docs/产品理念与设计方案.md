# 心仔 XINZAI · 娃娃心脏

第一版产品定义 / 2026-09-22

> 2026-09-23 更新：本文保留初版探索过程。用户后续明确需要独立 GNSS 离线记录、BLE 回连同步和 Android App；硬件选型以《京东硬件采购清单》、已确认范围以《补充对话需求合并》为准，手机定位现阶段作为 App 的可用记录来源。

## 1. 一句话讲清楚

**给娃娃一颗心，把一起走过的日常，变成它记得的回忆。**

用户选择的首版方向：共同回忆 + 轻陪伴。暂名「心仔」，正式使用前需要做名称、商标与应用商店重名检索。

它是一套“可放进娃娃随身口袋的情感硬件 + 私密回忆 App”。硬件代表娃娃在场，软件把共同经历组织成故事；娃娃的生命感来自有连续性的记忆、稳定的性格和适度的回应。

### 用户真正购买的价值

- “有人和我一起经历”的陪伴感：一杯咖啡、一次散步，也能变成共同记忆。
- “我的娃是独一无二的”的身份感：由用户定义名字、性格、偏好、重要日期。
- “喜欢可以被好好收藏”的仪式感：照片、地点、日期、文字都能被找回。
- “这是我们的故事”的表达感：一张可导出的精致回忆卡，私藏或自愿分享。

优先服务已经有娃、经常带娃出门拍照的用户；追星只是首批使用场景之一，也允许原创娃、毛绒玩具等。奶油风不是“女生只喜欢粉色”的假设，先提供低饱和中性色，后续根据用户反馈提供主题。

## 2. 参考产品与差异化

参考：[娃娃私密照片日记 - NuiDays](https://apps.apple.com/cn/app/id6756256399)。本次通过 Apple 公开查询接口读取到其商店介绍；确认其覆盖照片日记、地点与日期整理、地图与日历回看、搜索、回忆卡片与备份。没有把商店描述当成实际体验测试，也未据此推断付费率、用户规模或口碑。

保留值得借鉴的模式：低门槛记忆录入、围绕娃娃整理、随时回看、私密优先。页面布局、角色和文案独立设计，不复制对方素材。

心仔的差异化假设：

| 能力 | 用户能感知到的价值 | 首版范围 |
| --- | --- | --- |
| 心脏在场 | 带着实体娃娃出门有仪式感 | 蓝牙绑定、连接状态、手动替代 |
| 一次出门成为一篇故事 | 不用回家从零整理照片和地点 | 主动开始、地点候选、可编辑草稿 |
| 娃娃记得共同经历 | 回应与真实经历有关，不是随机卖萌 | 从用户保存的记忆提取简短回应 |
| 一眼认出的回忆卡 | 收藏和分享都有完成感 | 奶油手账、拍立得、旅程票根 |
| 回忆属于用户 | 换设备、停止订阅后仍能拿走 | 导出、删除、备份，分享地点默认隐藏 |

这些是产品策略假设，不能据此保证有市场。第一轮访谈要验证“是否愿意持续记录”和“实体心脏是否比纯软件多带来价值”。

## 3. 让娃娃“像活着”的五个设计原则

1. **有名字、有性格。** 用户可以选慢热、好奇、安静等表达偏好；不强制套用真人偶像的人格。
2. **记得具体的事。** 例如“我们又来这家咖啡馆了”，前提是用户确实保存过相关记录。没有数据就不装作记得。
3. **回应现实行为。** 成功连接时出现“我在你身边”；归途完成回忆时出现“今天的小事，我收好啦”。硬件可用短震动或微光强化仪式。
4. **给生活留白。** 允许只拍一张照片，不写文字；允许几周不打开；没有心情下降、饥饿、断签惩罚和情绪勒索。
5. **可控的想象空间。** 娃娃口吻是创作表达，不宣称玩偶有意识。生成内容可编辑、可关闭，区别用户原文、系统模板和 AI 草稿。

不把强聊天、大型公开社区、排行榜作为首版中心。这些会增加审核、运营与推理成本，也可能稀释共同回忆这个独特价值。

## 4. 硬件方案：先分清蓝牙与 GPS

蓝牙是连接与近距离感知技术，GPS/GNSS 是定位手段，二者不是一个“蓝牙 GPS”功能。普通蓝牙连接不能让远方设备自动向 App 上报位置。蓝牙近距离能力的依据可见 [Bluetooth SIG 的定位服务说明](https://www.bluetooth.com/learn-about-bluetooth/solutions/location-services/)。

| 方案 | 工作方式 | 适合场景 | 主要代价 |
| --- | --- | --- | --- |
| **A：BLE 心脏 + 手机定位（首版建议）** | 手机知道大致位置，心脏确认娃娃随行 | 用户带娃、带手机一起出门 | 依赖手机权限与后台策略；不等于独立防丢 |
| B：BLE + GNSS + 本地存储 | 硬件独立存轨迹，回到手机旁再同步 | 不带手机仍要记录旅程 | 增加天线、功耗、体积、存储与时间同步复杂度 |
| C：GNSS + 蜂窝联网 | 硬件定位后经网络上传 | 离开手机仍需远程报告 | 通信模块、流量、认证、续航与服务成本 |

“与娃一起出门”首先选择 A。按需记录停留地点通常比全程高频轨迹更贴合回忆产品。开机、连接、断连、暂停、结束、离线补传都要有明确状态，不把定位失败伪装成仍在持续记录。

移动系统限制必须真机验证：苹果后台定位需要匹配实际使用场景与权限，参见 [Apple 后台定位说明](https://developer.apple.com/documentation/corelocation/handling-location-updates-in-the-background)；Android 后台更新也有限制，参见 [Android 后台定位说明](https://developer.android.com/develop/sensors-and-location/location/background)。蓝牙信号强度也不能直接承诺准确距离。

### 外壳方向

- 主形态：扁圆心形、无锐边、奶油蜜桃色；备选为云朵、鹅卵石、星星。
- 体验：放进可拆卸小背心或独立心脏口袋，兼容不同娃体；避免要求用户拆开或破坏娃娃。
- 功能概念：BLE、低亮度状态灯、轻触/实体按键、可选短震动、可充电电池与保护电路。
- 尺寸与重量是工程目标，需按娃体尺寸、PCB、天线净空和电池实测后确定。现阶段不宣传续航天数、最小厚度或防水等级。
- 可选按键动作：短按在手机创建“想记住的一刻”，长按开关机或配对。若追求更轻薄，可先舍弃震动。
- 取出充电；外壳锁紧与电池保护、发热、跌落、小部件、清洁方式进入硬件验证清单。此处是工程任务清单，不是认证结论。

## 5. 首版 App 信息架构

| 入口 | 核心内容 | 首要操作 |
| --- | --- | --- |
| 陪伴 | 娃娃状态、温柔问候、出门入口、最近回忆 | 带我出门 / 接续旅程 |
| 足迹 | 地点地图、出门时间线、按地点回看 | 开始与结束旅程 |
| 回忆 | 照片手账、日期与标签、搜索、日历 | 留下瞬间、编辑、导出卡片 |
| 我的 | 娃娃身份、心脏连接、安静偏好、备份与隐私 | 编辑昵称、管理设备与数据 |

### 首次使用

用户选已有娃娃 → 上传头像 → 起名 → 选择轻陪伴语气 → 选择“连接心脏”或“先体验” → 保存第一份回忆。

权限放在需要时申请：选照片时请求所选照片，开始旅程时说明定位用途，配对时请求蓝牙权限。不要在首次启动连续弹出所有权限。

### 一次完整的出门

主动点“带我出门” → 确认心脏随行或选择手动记录 → 记录停留地点候选 → 用户补照片 → 结束旅程 → 提供可编辑日记草稿 → 用户确认保存 → 娃娃一句回应 → 可选导出卡片。

正式版的自动记录应该产出“待确认回忆”，避免把短暂停车、路过或定位漂移直接写成已经去过某店。失去心脏连接时提示状态；是否继续记录由用户决定。

### 照片功能分层

- 首版必需：从相册导入、压缩与元数据处理、时间/地点/标签、文字、封面、编辑删除、卡片导出。
- 第二阶段：多图手账、裁切滤镜、娃娃抠图贴纸、按娃检索、旅行专题相册、照片 EXIF 地点候选且需确认。
- 后续探索：AI 辅助编排与文字、回忆翻页小视频、实体记忆册。涉及 AI 生图时优先保留娃娃外观一致性，不自动改脸或改变用户照片。

## 6. 视觉与文案体系

整体方向：**温柔、可收藏、有呼吸感的奶油手账**。可爱来自角色质感、细节和语气，信息与按钮仍然清楚易用。

| 用途 | 颜色 |
| --- | --- |
| 奶油背景 | `#F8F6F0` |
| 卡片纸面 | `#FFFDF8` |
| 鼠尾草主操作 | `#6F7E5B` |
| 蜜桃情感点缀 | `#C88F82` |
| 可读正文 | `#4C493F` |
| 柔和边线 | `#EAE5DB` |

照片是主角；主要按钮使用绿，粉色仅强调心脏和情感。移动端采用底部四导航，桌面评审版采用左侧导航。圆角 12–24 px，细线图标，避免整屏碎花、过量贴纸和文字堆叠。

语气示例：

- 连接：“我在你身边。”
- 出门：“口袋里装着小小的我。”
- 保存：“今天的小事，我收好啦。”
- 久未打开：“回来啦，想记点什么都可以。”
- 无数据：“第一份回忆，等你来写。”
- 定位不可用：“暂时没能记住位置，可以手动写下这个地方。”

## 8. 卖点、商业模式与市场验证

对外主标题：“给娃娃一颗心，让每一次同行都有回忆。”

三个易传播的场景：第一场一起看的演唱会、第一家一起去的咖啡馆、第一次带娃远行。对外卡片应首先好看、像真实生活，再带小而克制的品牌署名；分享完全自愿。

### 收费假设

- 免费体验：单娃基本记录、手动地点、基础回忆卡、数据导出。
- 硬件一次购买：心脏本体与可选外壳/收纳配件。
- 可选订阅或素材包：更多卡片主题、多娃整理、跨设备同步、年度纪念册、额外生成额度。不要把用户既有记忆和基础数据导出锁在付费墙后。
- 价格暂不确定：先拿 BOM、打样、装配、包装、售后、渠道与云服务成本，再测试愿付价格。不能用没有成本支持的低价承诺倒逼产品。

### 先做低成本证据

1. 访谈 12–15 位真实带娃用户（数量为研究计划，不是已有样本）：查看她们现在怎么整理照片，最近一次没能记住的体验是什么。
2. 用本原型做任务测试：不解释流程，让用户完成出门、上传、编辑、回看、导出，观察卡点与文案理解。
3. 做 2 周小规模记忆记录试用，比较纯软件与心脏概念的价值感；先验证持续使用动机，再增加硬件研发投入。
4. 记录核心事件：首份回忆完成率、两周内再次保存、回看率、卡片导出率、手工修正比例、硬件愿付意愿、拒绝定位比例。目标阈值在试验前制定，不伪造行业基准。
5. 首批招募可考虑娃娃店、娃衣工作室、娃展以及真实玩家内容；合作、广告和授权需另行约定。本次未联系任何人或发布内容。

## 9. 技术落地与原型边界

产品原生端可在 Flutter / React Native / 原生方案之间按团队能力选择，定位与蓝牙功能优先做 iOS、Android 真机技术验证；不要把浏览器原型等同于可上架的安装包。

建议核心实体：Doll、DeviceBinding、Trip、LocationCandidate、Memory、Photo、GeneratedDraft、PrivacyPreference。照片通过数据库关联记忆，草稿保留来源与版本；行程和位置从采集到保存有明确生命周期。多设备之间的解绑、转让、同步冲突需要在后续设计补齐。

当前交付：无框架、无构建依赖的本地响应式 Web 交互原型；实际支持页面导航、上传本地图片、编辑/删除/搜索回忆、日历回看、模拟出门、生成本地模板草稿、PNG 回忆卡、JSON 备份导入导出、昵称与偏好持久化。

没有接入：真实蓝牙、后台定位、实际地图坐标、在线 AI、账号云同步、推送、支付、真实硬件。原型演示日期与照片是样例，不代表用户真实行踪。原创图片由内置 imagegen 生成，两个场景的娃娃外观存在细微差异；正式产品使用用户本人上传的真实娃娃照片。

本地存储是原型便利方案，不是加密存储或生产级照片库。清理浏览器数据会丢失内容，应导出备份；首版原生产品应采用系统私有文件目录/数据库、密钥安全存储和明确的备份恢复策略。

## 10. 下一阶段清单

- 用户测试修订界面与核心卖点。
- 完成移动端首次建档、配对、解绑与权限异常的详细交互。
- 选定一款开发板验证 BLE 在场与手机定位流程，实测后台行为、误断连和功耗。
- 结合真实娃体做外壳尺寸与装戴样件，再确认元器件、天线、充电结构和成本。
- 把本地原型数据层替换成原生/服务端持久化，加入多图、同步、权限与完整测试。

设计完成不等于研发完成；本阶段把理念、首版范围、视觉语言和关键交互变成可评审成果。
